# 福利吧预注册签到 - 青龙面板脚本

自动完成福利吧论坛(wnflb2023.com)「游客预注册签到」插件(`fuliba_prereg`)的每日签到。

预注册账号连续签到 30 天可免费转为正式会员，**漏签会中断连续天数**，所以需要每天稳定执行。

## 特性

- 两种认证方式：**Cookie 直签** 或 **账号密码登录**
- 账号密码模式带 Cookie 缓存：首次登录后缓存凭证，之后优先复用，缓存失效才重新登录
- 登录遇到图片验证码时自动用 **ddddocr** 本地识别（识别错会重新取图重试）
- 已签到自动跳过，可安全重复执行（幂等）
- 签到后输出连续天数 / 进度 / 距转正天数
- 多账号支持（换行分隔）
- Cookie 失效自动检测，推送告警提醒重新抓取
- 网络抖动自动重试，`formhash` 过期自动重取重试一次
- 复用青龙 `notify.py` 推送

## 认证方式怎么选

| 方式 | 环境变量 | 优点 | 注意 |
|---|---|---|---|
| Cookie 直签 | `WNFLB_COOKIE` | 简单直接，不触发登录 | Cookie 过期需手动更新 |
| 账号密码 | `WNFLB_ACCOUNTS` | 不会因 Cookie 过期而失效 | 该站**登录失败按 IP 计数**，连续失败 5 次要验证码 |

> ⚠️ **该站登录失败次数是按 IP 统计的**（实测：换新会话次数仍会递减，5 次后要求验证码）。
> 所以账号密码模式下脚本**认证失败绝不自动重试**（只有网络错误才重试），且缓存命中时
> 完全不走登录流程。请务必确认密码正确后再配置。

两种方式可以同时配置，会各自独立跑一遍。

## 接口流程

### 签到

| 步骤 | 请求 | 说明 |
|---|---|---|
| 1 | `GET plugin.php?id=fuliba_prereg:checkin` | 签到页，提取 `formhash`；游客访问会渲染预注册表单，据此判定 Cookie 失效 |
| 2 | `POST plugin.php?id=fuliba_prereg:checkin&ac=do` | body `formhash=xxx`，成功与幂等均返回 `302`，`Location` 形如 `...&done=<码>&d=<连续天数>` |

`done` 码语义（实测）：

| 码 | 含义 | 脚本处理 |
|---|---|---|
| `1` | 签到成功 | ✅ 成功 |
| `-2` | 今日已签到 | 🔁 成功（幂等） |
| 其他 | 未知状态 | ❌ 失败，输出结果页提示文案 |

> 注意：`ac=do` **必须用 POST**。GET 会被拒绝并提示「请通过签到页上的按钮提交本操作」。

### 登录（仅账号密码模式）

正常情况一步到位：

| 步骤 | 请求 | 说明 |
|---|---|---|
| 1 | `GET member.php?mod=logging&action=login&...&inajax=1` | 取 `formhash` + `loginhash` |
| 2 | `POST member.php?mod=logging&action=login&loginsubmit=yes&...&loginhash=<x>&inajax=1` | body `formhash` / `referer` / `username` / `password` / `questionid=0` / `answer=` / `cookietime=2592000` |

登录成功判定：响应含「欢迎您回来」或会话拿到 `S5r8_2132_auth` Cookie。

**同一 IP 连续失败 5 次后**，第 2 步不再直接成功，而是返回「请输入验证码后继续登录」并给出一个 `auth` 令牌，进入两步验证：

| 步骤 | 请求 | 说明 |
|---|---|---|
| 3 | `GET member.php?mod=logging&action=login&auth=<令牌>&...` | 取该页的 `formhash`、`auth`、`loginhash`，以及 `updateseccode('<idhash>', ...)` 里的 `idhash` |
| 4 | `GET misc.php?mod=seccode&update=<时间戳>&idhash=<idhash>` | 取验证码 PNG |
| 5 | `POST` 同第 2 步，额外带 `auth` / `seccodehash=<idhash>` / `seccodemodid=member::logging` / `seccodeverify=<OCR 结果>` | 验证码识别错会重新取图重试，最多 3 次 |

> ⚠️ **坑（脚本已处理）**：进入「待验证码」状态时，服务端**也会下发 `S5r8_2132_auth` Cookie**。
> 如果只用「拿到 auth Cookie」判登录成功，会把「待验证码」误判成「登录成功」，
> 后续签到才报 Cookie 失效。脚本把「需要验证码」的判定放在最前面，不会踩这个坑。

## 快速开始

### 1. 青龙面板安装依赖

在青龙「依赖管理」-「Python」中安装：

```
requests
```

账号密码模式建议再装一个（**可选**，仅当登录遇到验证码时才用到）：

```
ddddocr
```

> `ddddocr` 是惰性加载的——平时登录不需要验证码就不会 import 它，不装也能正常跑。
> 只有在站点要求验证码时才会用到；未安装时脚本会给出明确提示并建议改用 Cookie 模式。
>
> ⚠️ 本地 Windows 调试 ddddocr 若报 `_ARRAY_API not found` / `numpy.core.multiarray failed to import`，
> 是 numpy 2.x 与旧 onnxruntime 不兼容，`pip install "numpy<2"` 或升级 onnxruntime 即可。
> 青龙容器一般是 numpy 1.x 老环境，无需处理。

### 2. 配置环境变量

| 变量名 | 必填 | 说明 |
|--------|------|------|
| `WNFLB_COOKIE` | 二选一 | 完整 Cookie 字符串，多账号用换行分隔 |
| `WNFLB_ACCOUNTS` | 二选一 | 账号密码，格式 `用户名#密码`，多账号用换行分隔 |
| `WNFLB_HOST` | ❌ | 站点域名，默认 `www.wnflb2023.com`（有备用域名时填这里） |
| `WNFLB_PROXY` | ❌ | HTTP 代理，如 `http://172.17.0.1:7890` |
| `WNFLB_TIMEOUT` | ❌ | HTTP 超时秒数，默认 `25` |
| `WNFLB_NOTIFY` | ❌ | 是否推送，默认 `true` |
| `WNFLB_NOTIFY_ONLY_FAIL` | ❌ | 全部成功时静默，默认 `false` |
| `WNFLB_DEBUG` | ❌ | 调试模式（打印请求 URL / 状态码 / 跳转地址 / 登录响应），默认 `false` |

`WNFLB_COOKIE` 与 `WNFLB_ACCOUNTS` 至少配一个，两个都配会各自独立跑一遍。

代理优先级：`WNFLB_PROXY` > 青龙全局代理（`HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY` 等）> 直连。
青龙 `config.sh` 里的 `ProxyUrl` 对脚本无效。

### 3. 准备凭证

#### 方式 A：Cookie（推荐，最省事）

1. 用浏览器打开 https://www.wnflb2023.com/ 并登录
2. 按 `F12` 打开开发者工具，切换到「网络」(Network) 标签
3. 刷新页面，点击任意 `plugin.php` 或 `forum.php` 请求
4. 在「请求标头」中找到 `Cookie:`，复制**完整值**（所有键值对都要）

> 💡 关键 Cookie 是 `S5r8_2132_auth`（登录态）与 `S5r8_2132_saltkey`。
> 另外这个站还有 `X_CACHE_KEY`、`server_name_session` 等非 Discuz 的键，一并复制即可。
>
> ⚠️ 不要只复制部分键。缺 `S5r8_2132_saltkey` 时登录态无法还原，脚本会判定 Cookie 失效。

#### 方式 B：账号密码

```
WNFLB_ACCOUNTS = 你的用户名#你的密码
```

- 登录**不需要验证码**，脚本会自动完成登录并签到
- 登录成功后 Cookie 会缓存到脚本同目录 `wnflb_cookie.json`，之后优先复用
- 该文件已被 `.gitignore` 的 `*_cookie.json` 规则忽略，**只存 Cookie 不存密码**，可放心
- 账号若设置了**安全提问**，账号密码模式无法登录，请改用 Cookie 模式

#### 多账号格式（两种方式都用换行分隔）

```
账号1的凭证
账号2的凭证
```

> 请用**换行**分隔。Cookie 值里可能含 `&`，用 `&` 分隔会被截断。

### 4. 添加青龙任务

- 命令：`task wnflb_checkin/wnflb_checkin.py`
- 定时：`15 8 * * *`（每天上午 8:15，可自行调整）

> 脚本头部 docstring 里的 `cron:` 与上面一致，用 `ql repo` 拉库时会自动建任务。

## 常见问题

### Q: 提示「Cookie 已失效」？

A: 浏览器重新登录论坛，F12 抓取新 Cookie 更新 `WNFLB_COOKIE`。注意要复制**完整** Cookie（含 `S5r8_2132_auth` 和 `S5r8_2132_saltkey`）。若用的是账号密码模式，脚本会自动重新登录，无需手动处理。

### Q: 账号密码模式提示「账号或密码错误（该 IP 剩余尝试 N 次）」？

A: 先核对 `WNFLB_ACCOUNTS` 里的密码。**不要反复重跑试探**——该站失败次数按 IP 累计。建议先用 Cookie 模式（浏览器登录后抓 Cookie）确认账号能正常登录，再配账号密码模式。计数会在约 15 分钟后或一次成功登录后重置。

### Q: 账号密码模式日志出现「站点要求输入验证码」？

A: 这是同一 IP 累计登录失败触发的，属正常降级路径。脚本会用 ddddocr 自动识别验证码继续登录，识别错会自动重新取图重试（最多 3 次）。若提示「未安装 ddddocr」，按上面第 1 步装上即可；连续 3 次识别失败则建议改用 Cookie 模式。等失败计数重置后，登录会恢复成一步到位、不再要验证码。

### Q: 验证码老是识别不准？

A: 该站验证码是 4 位小字，图片很小（约 700 字节），OCR 偶尔会看错。脚本已内置「识别错就重新取图重试」的循环，通常一两次内能过。若长期识别率差，可改用 Cookie 模式绕过登录。

### Q: 账号密码模式第一次跑会不会每次都登录？

A: 不会。首次登录成功后 Cookie 会写入 `wnflb_cookie.json`，之后每天优先复用缓存，只有缓存失效（Cookie 过期）才重新登录。想强制重新登录，删掉该文件即可。

### Q: 提示「该账号设置了安全提问」？

A: 账号密码模式不支持安全提问。请改用 Cookie 模式（浏览器登录后抓 Cookie）。

### Q: 提示「formhash 已过期」或「请通过签到页上的按钮提交本操作」？

A: 脚本会自动重取页面重试一次。若持续失败，多为站点改了签到页结构，用 `WNFLB_DEBUG=true` 跑一次看跳转地址。

### Q: 每天几点跑比较稳？

A: 连续天数是按自然日计算的，建议固定一个时间（如早上 8~10 点），避免接近午夜执行时因网络延迟跨天。

### Q: 签到成功但连续天数没变？

A: 说明当天已经签过了（幂等返回 `done=-2`），属正常现象。
