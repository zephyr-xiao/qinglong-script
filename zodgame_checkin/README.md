# ZodGame 签到 - 青龙面板脚本

自动完成 ZodGame 论坛(zodgame.xyz)的每日收益:

- **每日签到**(dsu_paulsign 插件):随机心情签到,领取酱油奖励
- **BUX 广告任务**(jnbux 插件):逐个完成广告任务,每个 +2 点币(点币仅累积,不自动兑换)

## 功能特点

- **Cookie 认证,轻量无浏览器依赖**(仅 `requests`)
- **四类失败分开判定与告警**:Cookie 失效 / Cloudflare 拦截 / 网络异常 / 页面疑似改版,不再笼统报「失败」
  - CF 挑战页(403 `Just a moment`)以前会被误判成「Cookie 有效」,再报一句「无法提取 formhash」,把拦截伪装成解析失败;现在单独归类,并提示 `cf_clearance` 与抓取时的出口 IP/UA 绑定
- **广告任务按接口成败判定**:流程为 `do=click` → 等广告页真实倒计时 → `do=update` → **`do=check` 校验**,
  只有校验响应出现「检查成功」才计为完成。不再用「整页正文含『成功』二字」这种会误判的判据
- **广告观看时长取自广告页真实倒计时**(`var count=N`),不再写死 4 秒
- **签到 POST 带重试**:签到接口幂等(重复提交返回「今日已签到」),网络抖动不再一次即废
- **已签到/任务已完成自动跳过**,可安全重复执行(幂等)
- **无任务链接时只认站点明确文案**(「暂时没有广告任务可执行」),其余一律按「疑似改版」告警,不静默当成功
- **未加入 BUX 广告系统时按站点自身流程自动加入**(页面出现「开始参与任务」时触发)
- **代理自动回退**:`ZODGAME_PROXY` 留空时回退青龙全局代理(`HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY`)
- **`--check` 自检模式**:不签到、不执行广告任务,只验环境变量 / 代理 / Cookie / CF / 页面结构
- **多账号支持**(换行分隔),昵称取自页面用于区分账号
- **退出码三档**:全部成功 `0`、部分成功 `2`、全部失败 `1`,青龙任务列表一眼可辨
- 复用青龙 `notify.py` 推送,标题按成败与失败分类分档

## 青龙任务命令

```text
task zodgame_checkin/zodgame_checkin.py
```

建议定时:

```text
30 9 * * *
```

(每天上午 9:30,与脚本头部 `cron:` 一致)

## 环境变量

| 变量名 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `ZODGAME_COOKIE` | ✅ | - | 完整 Cookie 字符串,多账号用换行分隔 |
| `ZODGAME_PROXY` | ❌ | - | HTTP 代理,如 `http://192.168.1.100:7890`;留空时自动回退青龙全局代理(`HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY`),仍为空则直连 |
| `ZODGAME_NOTIFY` | ❌ | `true` | 是否调用青龙 `notify.py` 推送 |
| `ZODGAME_NOTIFY_ONLY_FAIL` | ❌ | `false` | 全部成功时静默(需 `ZODGAME_NOTIFY=true`) |
| `ZODGAME_DEBUG` | ❌ | `false` | 输出接口响应细节,并把关键响应落盘用于排错 |
| `ZODGAME_DEBUG_DIR` | ❌ | 脚本同目录 `_zodgame_debug/` | 调试产物目录 |
| `ZODGAME_AD_SECONDS` | ❌ | - | 强制广告观看秒数;留空则从广告页真实倒计时解析(推荐留空) |

### 退出码

| 码 | 含义 |
|---|---|
| `0` | 全部账号成功 |
| `2` | 部分账号成功 |
| `1` | 全部账号失败(或未配置 `ZODGAME_COOKIE`) |

## 获取 Cookie

1. 用浏览器打开 https://zodgame.xyz/ 并登录
2. 按 `F12` 打开开发者工具,切换到「网络」(Network)标签
3. 刷新页面,点击任意 `forum.php` 请求
4. 在「请求标头」中找到 `Cookie:`,复制完整值(包含 `qhMq_2132_auth`、`cf_clearance` 等所有键值对)

> 💡 关键 Cookie 是 `qhMq_2132_auth`(登录态)和 `cf_clearance`(Cloudflare 放行)。
> `cf_clearance` 与**抓取时的出口 IP 与 UA 绑定**:换代理、换网络、改 UA 后必须重新抓取,
> 否则会以「被 Cloudflare 拦截」告警。论坛 Cookie 本身长期有效。

多账号格式(换行分隔):

```
账号1的完整Cookie字符串
账号2的完整Cookie字符串
```

## 自检模式

首次部署或收到告警时,先跑自检确认环境与登录态(不签到、不执行广告任务):

```text
task zodgame_checkin/zodgame_checkin.py --check
```

```
📊 自检结果:1/1 个账号可用
```

## 常见问题

### Q: 提示「Cookie 已失效」?
A: 浏览器重新登录论坛,F12 抓取新 Cookie 更新 `ZODGAME_COOKIE` 环境变量。

### Q: 提示「被 Cloudflare 拦截」?
A: `cf_clearance` 与抓取时的出口 IP/UA 绑定。换了代理或网络后,用新出口 IP 重新抓一次 Cookie;
或把 `ZODGAME_PROXY` 设成与抓取时相同的出口。

### Q: 提示「疑似改版」?
A: 脚本只认站点明确文案。签到页 title 异常、或任务列表区块消失/无链接又无「暂时没有广告任务可执行」时,
会按疑似改版告警而不是静默跳过。设 `ZODGAME_DEBUG=true` 跑一次,把 `_zodgame_debug/` 里的响应发出来即可定位。

### Q: 签到显示成功但没奖励?
A: 签到奖励随机(酱油/榨菜等),数量随机,属正常现象。

### Q: BUX 提示「校验未通过」?
A: 广告未看完(中途关闭则今日不再显示)或未加入 BUX 系统。脚本会自动尝试加入;
若反复失败,先跑 `--check` 确认「已加入 BUX 广告系统」。

### Q: BUX 为什么有时一个任务都没有?
A: 站点对「今日无任务投放」与「今日任务已全部完成」**共用同一句文案**,无法区分,脚本按同一情况处理。

### Q: BUX 任务有时只完成部分?
A: 单任务领奖失败不影响其他任务,次日会重新执行。汇总里会显示「完成 N/M 个任务」。
